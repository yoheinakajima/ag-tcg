Part C — Turn-planning extractor v0
Create a reusable analysis module. Suggested path:
- src/ptcg_activegraph/analysis/turn_planning.py

It should be read-only and pure. It must not import production mutation/lifecycle/generation code.

Implement, at minimum:

1. Robust trace reader
   - Supports CABT sidecar JSON and Kaggle env replay-like JSON.
   - Handles gzip .json.gz sidecars.
   - Handles both string enum forms and integer enum forms for OptionType / SelectContext when possible.
   - If a context/type is unknown, record unknown, do not guess beyond a safe label.

2. TurnPlan / DecisionFrame extraction
   For every decision frame where a player acts:
   - game_id / source
   - step
   - turn
   - yourIndex / acting_player if inferable
   - phase/context
   - minCount/maxCount
   - selected indices
   - option summaries
   - active/bench summaries for both players, if visible
   - handCount/deckCount/prizeCount/discardCount
   - energyAttached/supporterPlayed/stadiumPlayed flags
   - observed log events since previous frame
   - action family: setup_active, setup_bench, main_play, attach, evolve, ability, retreat, attack, search_to_hand, discard, switch/to_active, end, unknown
   - legality sanity: selected indices in range and count within min/max when available

3. Turn-level plan features
   Aggregate per player/game:
   - first attack turn
   - first KO turn, from logs only
   - first prize taken turn, from logs/prize count only
   - setup bench count after setup
   - bench occupancy by turns 1/2/3
   - energy attachments by turn
   - turns ending without attack
   - main-phase End selected while non-End actions existed
   - search actions count and chosen card ids when visible
   - discard actions count and discarded card ids when visible
   - retreat/switch count
   - ability use count
   - hand size / deck count trajectory
   - dead/low-action turn count: main phase with only End or no productive option
   - invalid/timeout/error flags if present

4. Unsupported flags
   The extractor must explicitly mark these as unsupported unless observed in logs or computed by a trusted API:
   - lethal availability
   - exact damage if not in logs
   - missed KO
   - Boss/gust target correctness
   - spread placement correctness
   - hidden-hand contents
   - “best” action
   - counterfactual attack outcome

5. Unit tests for extractor using small inline synthetic trace snippets. Do not rely on huge sidecars for tests.

Part E — Loss-mode taxonomy v0
Create a deterministic loss-mode classifier from observable trace features.

Loss modes should be labels, not causal claims. Use conservative wording:
- setup_underdeveloped: low bench / no backup attackers by early turns
- energy_slow: low energy attachments / attack readiness lag
- attack_lag: first attack later than reference median
- prize_lag: first prize/KO later than reference median
- passive_main_phase: frequent End with non-End alternatives
- discard_pressure: high discard rate of energy/basic/evolution/search cards
- search_underuse_or_misuse: low search frequency or search-to-hand choices with weak development signal
- low_ability_usage
- long_game_resource_decay: deckCount/handCount collapse or too many nonproductive turns
- runtime_failure: invalid/timeout/error
- unsupported: insufficient trace info

For each label:
- define exact deterministic rule
- record evidence fields
- record confidence: low/medium/high based on sample size and whether direct logs support it
- never classify missed lethal unless Search API or exact attack outcome is used and validated separately.
