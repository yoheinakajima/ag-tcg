MISSION
Pass 36 created the standing event-first tournament engine v0. Pass 37 must make it safe to run as a Replit Scheduled Deployment.

Core problem to solve:
Pass 36 stores primary state in local files under data/tournament/. That is fine in the dev workspace, but Replit published deployments run from a snapshot and should not rely on files written to the deployment filesystem for durable state. The deployment version needs a persistent storage backend before we schedule it.

Goal:
Create a production-safe scheduled worker wrapper that:
- persists tournament ledger/projections/game sidecars outside the ephemeral deployed filesystem;
- can be invoked repeatedly by Replit Scheduled Deployments;
- is idempotent and bounded;
- never uploads/submits;
- keeps the same event-first semantics from Pass 36;
- can run in dev with file storage and in deployment with Replit App/Object Storage or another clearly available persistent backend.

PHASE D — Deployment lock / lease
Pass 36 has a local flock lock. That protects one filesystem instance but may not protect separate scheduled deployment instances if storage is external.

Add a production-safe best-effort lease:
- key: locks/tournament_tick.lock.json
- fields: tick_id, owner, started_at, expires_at, heartbeat_at
- refuse to run if a non-expired lease exists
- allow stale lock recovery after TTL
- always release lease on clean exit
- keep local flock too

If App Storage cannot guarantee atomic writes, state that this is best-effort and configure schedule interval conservatively. Do not overclaim perfect distributed locking.

Tests should cover:
- fresh lease acquired
- active lease blocks
- expired lease can be recovered
- release clears lock
- production without storage fails closed
