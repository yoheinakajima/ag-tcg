Primary objective:

This should prepare us for a later serious cg_typed pilot, but this pass itself must not create a candidate.

Key principle:
Do not fabricate exact-damage/lethal/missed-KO claims. The Search API may allow exact one-step outcomes under certain state-completeness assumptions, but the pass must explicitly classify evidence as:
- exact_full_state_replay: calibrated against complete trace/full state and matches next frame/log delta.
- assumption_based_hidden_state: uses observed state plus hidden-zone assumptions; useful but not exact.
- unsupported_or_failed: failed, timed out, mismatched, or cannot be trusted.

Do not claim “best action” unless it is explicitly scoped as “best under this one-step scoring function and this search-state assumption,” never as globally optimal.

E. One-step action ranking diagnostic
Build:
scripts/build_pass46e_one_step_planner_diagnostic.py

Using only frames where the oracle calibration says the search result is supported enough:
- enumerate legal single-option actions, respecting minCount/maxCount.
- For multi-select contexts, start with actual selected action and small bounded combinations only; do not explode combinatorially.
- Score outcomes with a transparent generic_progress_v0 function:
  positive:
    win/result improvement
    prize count progress
    opponent active HP reduction
    own prize remaining reduction
    energy attached to a Pokémon that can plausibly attack
    search result that improves board development
    avoiding pass/end when productive options exist
  negative:
    invalid/error/timeout
    own prize loss
    deckout risk
    no-op/pass with productive alternatives
    excessive discard of visible useful resources
- This is NOT “best action”; call it one_step_score_rank under assumptions.

Compare chosen action rank distribution for:
