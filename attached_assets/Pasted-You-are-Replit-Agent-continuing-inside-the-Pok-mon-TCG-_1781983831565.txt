MISSION
We are done creating one-off passNN tournament scripts as the main operating mode. Pass 36 should promote the repeated tournament pattern into a standing, reusable, event-first tournament engine.

Build the smallest reliable v0 of a persistent tournament system that can later run continuously on Replit deployment via bounded ticks. It should NOT yet auto-generate new candidates or auto-submit to Kaggle. It should create the durable substrate:

- deterministic scheduler

- projections folded from events
- rankings / lineage / pool state
- no-upload dry-run decision state
- docs/tests/report

This is consolidation over the proven repo substrate, NOT a rebuild.

PHASE D — Deterministic scheduler v0
Implement a deterministic scheduler that chooses the next game/matchup from candidate pool + current projections.

The scheduler should not try to complete an entire tournament in one call. It should produce a bounded worklist for a tick.

Deterministic priority order:
1. Validation/smoke gaps for active/probation candidates, if any.
2. New/probation candidates vs anchors:
   - held probe vs water control
   - new deck vs portfolio reference
   - new deck vs family champion
3. Parent-child confirmation:
   - child vs parent, seat-swapped
4. Top bracket maintenance:
   - top 6 active candidates round-robin, least-played matchup first
5. Exploration:
   - active candidates with fewest total games
   - new family candidates get a temporary priority boost until min placement games reached
6. Regression sentinels:
   - periodic matches vs known weak/broken controls only if they are smoke-valid and active; do not include Toxic/Durant until special pilot exists.

Tie-breakers:
- lower number of completed games for matchup
- older last_played timestamp first
- lexicographic candidate_id
- deterministic seat alternation

Config:
data/tournament/config.yaml:
- tick_max_games default 50
- tick_max_seconds default 900
- per_game_timeout_seconds default 90
- active_soft_cap 16
- active_hard_cap 24
- min_placement_games_per_candidate 20
- min_parent_child_games_per_seat 10
- top_bracket_size 6
- exploration_ratio maybe 0.25
- auto_submit false
- max_dry_run_queue 1

Behavior:

- Emits GameScheduled and GameStarted before running each game.

- Stops cleanly at max-games or max-seconds.
- Re-running should resume from ledger/projections and not duplicate finished games.
- Must be safe to run repeatedly in Replit dev or deployed environment.
- No infinite loop in this pass.
- No upload.
- No candidate generation.
- No deleting old data.

Important: if Replit background shell dies, the tick must remain safe to rerun. Do not depend on a child process surviving outside the current call.
