# Improve main.py scoring conservatively

Update `main.py` only.

Keep all existing safety properties:

* stdlib-only
* self-contained
* no external calls
* no imports from `src`
* never raises outward
* returns deck when `select is None`
* always returns list[int]
* validates/clamps result
* generic string scorer remains as fallback

Add structured scoring in `_score_option` or equivalent.

Rules:

1. If option is a dict and `option.type == 13`, strongly prefer it as an attack.

   * Add a large positive score.
   * Add extra if `attackId` exists.
   * Do not blindly choose attack if there are required multi-select contexts, but for `maxCount=1`, type 13 should usually win over pass/end.

2. Deprioritize likely pass/end/no-op options only when there are alternatives.

   * Use actual examples to identify type 0/type 1 only if schema supports it.
   * Do not over-penalize unknown types.

3. Prefer card-action types that seem to correspond to productive card choices.

   * Use observed examples, not guesses.
   * Add comments documenting uncertainty.

4. Keep string scoring:

   * attack, damage, knockout, prize, evolve, energy, attach, draw, search, supporter, item, ability, skill, bench, switch, retreat, stadium
   * end, pass, done, concede negative

5. Add reason/debug support only outside hot path or behind simple helper, not required by Kaggle runtime.

6. Add regression tests using real option examples where possible:

   * type 13 attack outranks obvious end/pass
   * `main.agent` still returns deck on `select=None`
   * malformed observations still do not crash
   * returned indices are always in range
   * `maxCount` and `minCount` respected
